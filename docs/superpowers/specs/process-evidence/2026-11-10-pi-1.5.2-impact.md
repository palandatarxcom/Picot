# Pi 1.5.0 → 1.5.2 上游影响评估

**日期：** 2026-11-10  
**评估基线：** `scripts/pi-version.json` 在本轮开始时为 1.5.0；检查过程中该文件改为 1.5.2，且出现未跟踪的 `tests/fixtures/pi-rpc/1.5.2/`。这两项工作区改动均未由本评估修改；本文不判断其校验状态。
**上游标签：** `v1.5.0` → `v1.5.2`；本地 HEAD 为 `v1.5.2-100-ga40abecaa`。报告只依据标签内容，不把标签后的 100 个提交算入本次升级。

## 结论

**兼容判断：未发现需要 Picot 修改 RPC、SessionManager 或现有扩展命令的破坏性变更，也没有发现由 1.5.2 引入的进程关闭回归。** Picot 对 Pi 子进程的既有策略是 Unix 下 SIGTERM 后最多等待约 200 ms，再 SIGKILL（`src-tauri/crates/picot-host/src/process_tree.rs:64-86`）；因此 1.5.2 增强的 orderly shutdown 等待在 Picot 常规 stop 路径中不会获得完整发挥，但不会改变既有停止保证。

## Picot 集成面（判定依据）

- 扩展命令：`extensions/picot-bridge.ts:35-76` 注册 4 个命令；调用 `ctx.reload()`（45 行）和 `ctx.navigateTree()`（61 行）。
- SDK/会话：`extensions/picot-config.ts:185-196` 使用 `SessionManager.listAll/open/appendSessionInfo`；`783-788` 使用 `createAgentSession` 与 `SessionManager.inMemory()`。
- RPC 事件：`extensions/ephemeral-runtime-state.ts:226-232` 消费 `agent_start/agent_end`，并在 137-222 行处理消息、工具及模型事件。
- Pi 进程退出：`NativePiManager::stop()` 调用 `PiRpcProcess::kill()`（`src-tauri/crates/picot-host/src/native_pi_manager.rs:1151,1233`）；Unix 下进程树先 SIGTERM，最多等待约 200 ms 后 SIGKILL（`src-tauri/crates/picot-host/src/process_tree.rs:64-86`）。这是 1.5.2 之前已有的 Picot 行为。

## 新增功能

- **1.5.2：** 原会话目录已移动/删除时，可将会话 fork 到当前目录。Picot 使用 Pi 的会话树和历史能力，用户可能直接获得此上游能力；无需 Picot 改码。具体交互是否从 Picot 暴露，需 smoke 确认。
- **1.5.1：** 支持通过 `~/.pi/models.json` 配置自定义模型，并调整 `ModelRuntime` 对内置 provider、配置模型和扩展 provider 的组合方式。Picot 可随 Pi 获得此能力；Picot 自己的模型配置已走 Pi 的模型/runtime 接口，没有发现需额外接入的改动。
- **1.5.0：** 增加扩展更新 changelog 展示、流式渲染优化及自定义 Pi 更新命令。前两者是 Pi/TUI 体验，最后一项是 Pi 更新路径；Picot 没有对应调用点，无需移植。

## 影响 Picot 的修复与行为变化

- **RPC 关闭行为调整（1.5.2）：** Pi 通过 stdin EOF、SIGTERM 或 SIGHUP 进入 orderly shutdown，会等 pending work；第二个信号立即退出。Picot 的短 SIGTERM 窗口是既有行为，所以这不是本次升级回归，也不要求改码。若未来要求 Pi 完成优雅关闭，应改为先关闭 RPC stdin 并给足等待时间，避免 SIGTERM/SIGKILL 阶梯中断清理。
- **1.5.1/1.5.0 的 provider 与工具修复：** 包含模型请求格式、MCP 消息大小/stdio 子进程、工具 schema 与搜索等修复。Picot 通过 Pi 提供模型/MCP/工具能力，属于内嵌 Pi 自动获得的收益；没有证据表明 Picot 自己的 bridge/SessionManager 调用需要改变。
- **1.5.0 工具参数验证变更：** TypeBox 非 JSON Schema 特性不再用于工具参数校验，属于 Breaking Changes。但 Picot 集成面没有直接使用这些特殊 schema 功能的证据；对已审查的 4 个 Picot 扩展命令无影响。若 Picot 扩展另行注册带 `Type.Refine/BigInt/Undefined/codecs` 的工具，应单独迁移到 JSON Schema 兼容约束。
- **其他可见修复：** `/tree` 摘要尊重 context edits，CJK 工具搜索、Claude/GPT/Bedrock/OpenRouter 请求等有修复。它们属于 Pi 会话/模型内部行为或终端呈现，不要求 Picot 代码改动。

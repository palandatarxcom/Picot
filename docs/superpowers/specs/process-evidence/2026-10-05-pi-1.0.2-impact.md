## 修复与行为变化

### 随内嵌运行时升级受益

- codemode 无限打印不再一直吃内存至进程崩溃：输出超过 16 Mi 字符或 100000 项时脚本失败（#10283）。这不是内存完全受限的保证，但对 Picot 的 Pi 子进程稳定性有实际价值。
- “Selected model is at capacity” 改为可重试错误（#10278）。
- Anthropic 中途新增/重定义工具使用 inline tool_addition，避免因同名工具重定义重发工具列表、破坏 prompt cache。
- Bedrock Claude 在系统提示词/工具变化后的 thinking signature 错误修复（#10324）；Bedrock OpenAI 长上下文计价修复（#10326）。
- Cloudflare AI Gateway Claude 模型 ID 修复；Together DeepSeek V4 Pro 改名后的思考控件恢复（#10336）；NVIDIA 默认模型指向现存 Ultra 型号。仅相应 provider 用户受益。
- brace-expansion 直接依赖固定到 5.0.12，修复安全依赖解析问题（#10288）。不能仅凭 Picot 使用 binary 就断言其内嵌依赖与该修复完全无关；新二进制依赖情况属于升级核验范围。

### 主要属于上游 TUI/安装渠道

- OAuth 登录 URL 可用 ctrl+x 复制。
- JPEG/GIF/WebP 在 Kitty 系终端渲染修复、WezTerm 图片滚动修复。
- MCP 历史调用在 TUI/HTML export 中错误展开修复。
- `--models` 尾随逗号修复；Picot 是否传该参数应以启动 argv 为准，不能由“下载 binary”推导。
- npm 全局 `pi update` 推荐 managed installer；published package 移除 npm-shrinkwrap。

Codex 的浏览器回调端口已占用时现在明确失败（#10265）。Picot 当前仅允许 `device_code`（`extensions/picot-config.ts:1280-1288`），因此不是当前 GUI 登录路径的直接修复。AuthEvent/ModelRuntime 登录接口没有发现破坏性变化。

## MCP 项目覆盖：需要关注的具体差异

上游 `packages/coding-agent/src/extensions/mcp/config.ts:73-118`：

- 仅项目层、无 command/url/type 的条目可被当作 override。
- 必须存在同名全局基础服务器。
- 覆盖条目只能设置 enabled、exposure、toolExposure。

例子：

```json
{
  "mcpServers": {
    "context7": { "enabled": false, "exposure": "direct" }
  }
}
```

这表示在该项目中覆盖全局 context7，并非重新定义连接。

Picot `extensions/mcp-settings.ts:196-246` 的列表路径直接投影配置条目，不调用 normalizeEntry；**不能断言此配置会使列表读取抛 transport 错误**。但 `normalizeEntry` 最终校验要求 command/url，并由 saveMcpServer 调用（`extensions/mcp-settings.ts:299-427`）。因此现有保存路径不能完整支持纯 override。前端如何显示、编辑、启停，以及是否意外改写成完整定义，尚未做行为测试。

建议在授权升级时先对纯 override 做列表、编辑保存、启停、删除回归。若要支持，应保持覆盖语义，而不是机械取消 transport 校验；普通新建服务器仍须校验连接配置。

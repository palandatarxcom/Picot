## Dr. Lin 三个问题的结论

1. **原生 MCP 配置文件**：用户级 `~/.pi/agent/mcp.json`，项目级 `.pi/mcp.json`（需 project trust），格式 `mcpServers`，与其他 MCP 客户端一致。**不是** `mcp-adapter.json`。Picot 已在 1.0.4 周期切换：`extensions/mcp-settings.ts:271,675` 读写的就是这两个 `mcp.json`；`mcp-settings.ts:360-395` 把全局/项目 `mcp-adapter.json` 当作只读迁移源（用户确认后拷贝，从不回写）。MCP 设置页无条件可用（`public/settings/mcp-page.js:267-271`，注释明确 "Native MCP ships with every Pi 0.99+ runtime"）。本机 `~/.pi/agent/extensions/` 与 `packages/` 均无 pi-mcp-adapter，**已处于卸载后状态**；仓库运行时代码无任何 pi-mcp-adapter 引用。
2. **codemode 开关**：已实现。`extensions/picot-config.ts:1075-1109` 的 `get/set_default_codemode` 以 merge-token 方式写 `~/.pi/agent/settings.json` 的 `defaultTools: ["+codemode"]`，带 settings lock，测试在 `picot-config.test.ts:253-318,987-994`。1.1.0 文档 `cli.md` "Enable codemode" 语义未变；1.1.0 新增的 `--tools +codemode` 单次调用形式与 Picot 无关（Picot 不传 `--tools`）。**无需新增参数。**
3. **OAuth 登录 openai-codex**：无变化。Picot 走公开 SDK `ModelRuntime.login(...)`，1.1.0 未动该 API。相关修复（Codex 请求头覆盖 #10429、MCP OAuth 可取消/超时）全部内部透明继承。
